# Система мониторинга микроклимата

Учебный проект: DHT22 → ESP32 → USB → Python → SQLite.
Это консольная логика сбора и хранения данных с демонстрацией в Jupyter. Графический интерфейс ещё не реализован. MQTT отложен; способ получения данных отделён от БД.

## Запуск на Mac

1. Распакуй эту папку отдельно от исходного проекта и открой её в VS Code.
2. Выбери существующее окружение conda `microclimate` и это же ядро в блокнотах.
3. Если зависимостей нет: `python -m pip install -r requirements.txt` в активном окружении.
4. Открой `notebooks/01_database.ipynb`, запусти сверху вниз. Он показывает модель через семь запросов. Повторный запуск справочники не дублирует.
5. Подключи ESP32 с имеющейся прошивкой, закрой монитор порта Arduino IDE.
6. Открой `notebooks/02_receive_data.ipynb`, проверь `port` и выполни сверху вниз. Получатся пять новых пар с проверкой порогов. Без платы можно пропустить шаг сбора и посмотреть сохранённые данные.
7. После изменения Python-модулей перезапусти ядро и выполни блокнот заново.

## Файлы

- `notebooks/01_database.ipynb` — подготовка БД и семь содержательных запросов.
- `notebooks/02_receive_data.ipynb` — получение, сохранение и просмотр.
- `notebooks/microclimate.db` — исходная база пользователя: 44 измерения, два порога, ноль предупреждений на момент получения архива.
- `schema.sql` — исходная схема семи таблиц без изменения структуры.
- `db.py` — единое подключение с внешними ключами и `sqlite3.Row`.
- `repo.py` — справочники, запросы, пороги и транзакция сохранения пары.
- `receiver.py` — разбор входной строки и ограниченный сбор через USB.
- `microclimate_esp32/microclimate_esp32.ino` — исходная прошивка.

## Что изменено

Убраны промежуточное чтение десяти строк, разбор `sample`, ручная запись одной пары и искусственное измерение 30 °C. Функции больше не зависят от порядка старых ячеек. Код работы с БД перенесён в модули; идентификаторы каналов определяются запросом по узлу ESP32-001. Путь базы задаётся относительно проекта: файл остаётся в notebooks. Выводы ячеек очищены, чтобы при показе получать фактический результат текущего запуска.

## Договорённости

Время приёма хранится в ISO-8601 UTC с `Z`. Период порога: начало включительно, окончание исключительно; NULL означает отсутствие окончания. Равенство границе допустимо. 20–26 °C и 40–60 % — демонстрационные настройки, не нормативы. Начальные пороги не применяются задним числом. При пересечении действующих правил выдаётся ошибка, смена границ через set_threshold закрывает прежний бессрочный период и создаёт новый.

Один DHT22 у текущего узла даёт два канала. Минимальные количества дочерних объектов не гарантируются одними внешними ключами; получение каналов проверяет их наличие. Транспорт USB можно впоследствии заменить MQTT, сохранив логику БД. Синхронный сбор предназначен для notebook: для GUI понадобится фоновый исполнитель и управление состояниями.

## Проверено при подготовке

Целостность исходной базы и внешние ключи; сохранность исходных данных и прошивки; запуск первого блокнота дважды на временной копии; просмотр из второго блокнота без платы; разбор корректных/повреждённых строк; превышение, занижение, равенство границам, отсутствие и пересечение порогов; откат пары при ошибке; сбор и тайм-аут с имитацией последовательного порта. Реальная ESP32 в среде подготовки недоступна: запуск по USB на Mac нужно проверить после распаковки.


## Создание окружения conda на другом компьютере

Из корня проекта:

```bash
conda env create -f environment.yml
conda activate microclimate
```

Если окружение `microclimate` уже есть, создавать его снова не нужно. В VS Code выбери его ядро. Arduino-зависимости устанавливаются отдельно: поддержка плат ESP32, Adafruit DHT sensor library и Adafruit Unified Sensor. Для прошивки GPIO4 — DATA DHT22, питание 3.3 В и общий GND. Перепрошивка для этой версии не требуется.

## Смена порогов с сохранением истории

Функция `repo.set_threshold(conn, channel_id, lower, upper)` начинает новый период с текущего UTC-времени и закрывает предыдущий бессрочный. Передавай идентификатор из `get_channels(conn)`. Например, в отдельной ячейке после подключения:

```python
from repo import get_channels, set_threshold
channels = get_channels(conn)
set_threshold(conn, channels["temperature"], 20.0, 27.0)
```

Это реальная смена настроек, поэтому выполнять пример при каждом показе не нужно. Функция сама управляет транзакцией; вызывай её вне другой транзакции. Старые предупреждения сохраняют ссылку на старые границы. Первичная инициализация существующие правила не меняет.

## Подготовка к GitHub

В репозиторий входят Python-код, схема, блокноты без сохранённых выводов, прошивка, тесты, описание модели и окружения. `.gitignore` исключает рабочие SQLite-базы, окружения, кэш и локальные настройки. База с реальными показаниями остаётся в локальной папке и в переданном архиве. После клонирования первый блокнот создаст новую базу, справочники и учебные пороги; история измерений будет пустой до подключения ESP32.

Перед коммитом после работы в Jupyter очисти выводы ячеек и сохрани блокноты, чтобы не публиковать локальные пути и устаревшие результаты. `.gitignore` сам по себе не очищает выводы notebook.

## Границы текущего этапа

Готовится часть до GUI: приём, валидация, транзакции, история измерений и порогов, предупреждения, семь запросов и автоматические проверки. Состояния окна, потоки, графики и формы не реализованы. Для GUI нельзя выполнять синхронный collect_pairs прямо в обработчике кнопки: понадобится фоновый исполнитель. ML остаётся отложенным согласно текущему плану; требования итоговой курсовой нужно учитывать отдельно.

Схема и кратности подробно описаны в [MODEL.md](MODEL.md).
